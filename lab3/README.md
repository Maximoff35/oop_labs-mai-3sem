# Лабораторная работа №3

Вариант 13. `Temperature` — температура (значение и единица измерения).

Программа реализует класс `Temperature` и множество `TemperatureSet` на основе динамического массива `Temperature*`. Поддерживаются градусы Цельсия, Фаренгейта и Кельвины; перед сравнением температуры приводятся к градусам Цельсия с округлением до `10⁻⁶` °C. Исходное значение и единица измерения сохраняются.

Множество не отсортировано: элементы хранятся в порядке добавления, дубликаты не допускаются, удаление выполняется со сдвигом элементов. Контейнеры STL и умные указатели не используются; память управляется вручную через `new[]` и `delete[]`.

## Что реализовано

Класс `Temperature`:

- конструкторы по умолчанию и с параметрами;
- `value`, `unit` — получение исходного значения и единицы измерения;
- приведение к Цельсиям для сравнения температур;
- `operator==` — сравнение температур с учётом канонизации;
- `operator<<` — вывод температуры в поток;
- проверка корректности единицы измерения и границ абсолютного нуля.

Класс `TemperatureSet`:

- динамический массив с полями `data_`, `size_`, `capacity_` и удвоением ёмкости при заполнении;
- деструктор, конструкторы копирования и перемещения, операторы присваивания (правило пяти);
- копирующее присваивание по идиоме copy-and-swap, перемещающие операции с `noexcept`;
- `add`, `remove`, `contains`, `operator()` — добавление, удаление и проверка принадлежности;
- `size`, `empty` — количество элементов и проверка на пустоту;
- `operator+=`, `operator-=` — добавление и удаление одного элемента;
- `operator|`, `operator&`, `operator-` — объединение, пересечение и разность множеств;
- `operator==`, `operator!=` — сравнение множеств независимо от порядка элементов;
- `operator<<` — вывод элементов в порядке добавления.

Особенности варианта 13:

- `0 C` и `32 F` считаются одной температурой, поэтому второй `add` не изменит множество;
- поиск дубликатов линейный;
- удаление сохраняет порядок оставшихся элементов.

Пример вывода множества:

```text
{ 25 C, 32 F, 300 K }
```

## Сборка

Проект собирается через CMake с использованием стандарта C++20. При первой конфигурации CMake загружает Google Test через FetchContent; для этого нужен доступ к GitHub.

```powershell
cmake -S . -B build -G Ninja
cmake --build build
```

Отдельная демонстрационная программа не предусмотрена: запуск и проверка реализованы через Google Test.

## Тесты

Для тестирования используется Google Test (**31 тест**: 11 для `Temperature` и 20 для `TemperatureSet`).

Запуск тестов напрямую:

```powershell
.\build\lab3_tests.exe
```

Или через CTest:

```powershell
ctest --test-dir build --output-on-failure
```

В тестах проверяются конструкторы, преобразование единиц и сравнение температур, корректность добавления и удаления, дубликаты, сохранение порядка, глубокое копирование, перемещение, присваивание, самоприсваивание, операции над множествами, вывод и стресс-тест на 1000 элементов.

**Результат проверки:** 31 из 31 тестов пройдены.

## Проверка памяти

Для проверки обращений к памяти используется AddressSanitizer со сборкой Clang в MSYS2 CLANG64:

```bash
cmake -S . -B build-asan -G Ninja \
  -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_CXX_COMPILER=clang++ \
  -DCMAKE_CXX_FLAGS="-fsanitize=address -fno-omit-frame-pointer" \
  -DCMAKE_EXE_LINKER_FLAGS="-fsanitize=address"
cmake --build build-asan
ctest --test-dir build-asan --output-on-failure
```

Все 31 теста прошли в ASan-сборке, ошибок обращения к памяти при выполнении тестов не обнаружено. Проверка AddressSanitizer не гарантирует обнаружение всех утечек памяти на Windows.
